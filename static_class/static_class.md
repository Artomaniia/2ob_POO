
## 1. Что такое статический класс?

**Статический класс** — это класс, который не предназначен для создания экземпляров (объектов). Все его члены (методы и атрибуты) являются статическими, то есть принадлежат самому классу, а не конкретному объекту. В таких языках, как C# или Java, статический класс объявляется ключевым словом `static` и не может быть инстанциирован. В Python **нет встроенной конструкции «статический класс»**, но его поведение легко эмулируется с помощью обычного класса и декораторов.

Основное назначение статического класса — служить **контейнером для логически связанных утилит, констант или вспомогательных функций**, которые не требуют состояния экземпляра.

---

## 2. Зачем нужен статический класс в Python?

- **Организация кода** — сгруппировать родственные функции и константы под одним именем.
- **Пространство имён** — избежать загрязнения глобальной области видимости.
- **Чистота интерфейса** — явно показать, что класс не предназначен для создания объектов.
- **Имитация статических классов из других языков** — при портировании кода или сохранении знакомой структуры.

Однако **в Python более идиоматичным способом** является использование **обычного модуля**: модули уже являются «статическими контейнерами» по своей природе. Тем не менее, статический класс может быть удобен, когда нужно:
- использовать наследование;
- применять декораторы класса (например, `@dataclass` для статических конфигов);
- сохранить единый интерфейс в рамках ООП-проекта.

## 3. Как реализовать статический класс в Python?

### 3.1. Простейший вариант — все методы статические

Создаём класс, помечаем все методы декоратором `@staticmethod` (или `@classmethod`, если нужен доступ к атрибутам класса). Чтобы запретить создание экземпляров, переопределяем `__new__` или выбрасываем исключение в `__init__`.

**Пример:**

```python
class StaticMath:
    """Статический класс для математических утилит."""

    # Статическая константа
    PI = 3.14159

    def __new__(cls, *args, **kwargs):
        """Запрещаем создание экземпляров."""
        raise TypeError(f"Класс {cls.__name__} является статическим и не может быть инстанциирован")

    @staticmethod
    def add(a, b):
        return a + b

    @staticmethod
    def circle_area(radius):
        return StaticMath.PI * radius ** 2
```

**Использование:**

```python
>>> StaticMath.add(5, 3)
8
>>> StaticMath.circle_area(10)
314.159
>>> obj = StaticMath()  # TypeError: Класс StaticMath является статическим...
```

### 3.2. Альтернативный запрет создания экземпляров

Можно просто переопределить `__init__` и бросить исключение, но это не помешает вызвать `__new__` и получить объект (хотя в данном случае `__new__` вернёт экземпляр, а `__init__` его не инициализирует — объект всё равно будет создан, но без атрибутов). Поэтому надёжнее переопределять `__new__`.

### 3.3. Использование `@classmethod`

Если нужно обращаться к атрибутам класса (и, возможно, к переопределённым в подклассах), используют `@classmethod`:

```python
class Config:
    _settings = {"theme": "dark", "language": "ru"}

    def __new__(cls, *args, **kwargs):
        raise TypeError("Config — статический класс")

    @classmethod
    def get(cls, key):
        return cls._settings.get(key)

    @classmethod
    def set(cls, key, value):
        cls._settings[key] = value
```

## 4. Примеры использования

### 4.1. Утилитный класс для работы с датами

```python
class DateUtils:
    """Статический класс для операций с датами."""

    MONTH_DAYS = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

    def __new__(cls, *args, **kwargs):
        raise TypeError("DateUtils — статический класс")

    @staticmethod
    def is_leap_year(year):
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)

    @classmethod
    def days_in_month(cls, month, year):
        if month == 2 and cls.is_leap_year(year):
            return 29
        return cls.MONTH_DAYS[month - 1]
```

### 4.2. Статический класс с декоратором `@dataclass` (для конфигурации)

```python
from dataclasses import dataclass

@dataclass(frozen=True)  # неизменяемый статический конфиг
class AppConfig:
    """Статическая конфигурация приложения."""
    APP_NAME: str = "MyApp"
    VERSION: str = "1.0.0"
    DEBUG: bool = False

    def __new__(cls, *args, **kwargs):
        raise TypeError("AppConfig — статический класс")

# Использование:
print(AppConfig.APP_NAME)  # MyApp
# AppConfig.APP_NAME = "New"  # frozen -> ошибка
```

### 4.3. Наследование статических классов

Статические классы могут наследоваться. Потомки также должны быть статическими (или можно разрешить создание экземпляров, но это нарушает замысел).

```python
class BaseConverter:
    def __new__(cls, *args, **kwargs):
        raise TypeError("BaseConverter — статический класс")

    @staticmethod
    def kg_to_lbs(kg):
        return kg * 2.20462

class ExtendedConverter(BaseConverter):
    @staticmethod
    def lbs_to_kg(lbs):
        return lbs / 2.20462

# Использование:
print(ExtendedConverter.kg_to_lbs(5))  # 11.0231
print(ExtendedConverter.lbs_to_kg(11)) # 4.9895
```

## 5. Статический класс vs Модуль

В Python наиболее естественный способ создать «статический контейнер» — использовать **модуль**. Файл `mymodule.py` с функциями и переменными уже является статическим объектом, который импортируется один раз и не требует инстанцирования.

| Критерий                | Статический класс                              | Модуль                                      |
|-------------------------|------------------------------------------------|---------------------------------------------|
| **Синтаксис доступа**   | `ClassName.func()`                             | `module.func()`                             |
| **Наследование**        | Поддерживается                                 | Не поддерживается                           |
| **Состояние**           | Можно через атрибуты класса (глобальное)       | Глобальные переменные модуля                |
| **Запрет инстанцирования** | Приходится писать `__new__` явно           | Не применимо (модуль не создаётся как объект) |
| **Идиоматичность**      | Менее Pythonic (но допустима в ООП-проектах)   | Полностью Pythonic, рекомендуемый подход    |
| **Подсказки типов**     | Работают как обычно                            | Работают как обычно                         |

**Вывод:** для большинства задач лучше использовать модуль. Статический класс оправдан, если:
- Вы пишете код в рамках крупной ООП-системы, где все сущности — классы.
- Вам нужно наследование и полиморфизм на уровне статических методов.
- Вы переносите код из Java/C# и хотите сохранить знакомую структуру.

## 6. Лучшие практики и нюансы

1. **Явно документируйте**, что класс статический, и запрещайте создание экземпляров. Добавьте комментарий в docstring и вызов `TypeError` в `__new__`.
2. **Не смешивайте** статические и обычные методы в одном классе — это сбивает с толку.
3. Для хранения констант внутри статического класса используйте `UPPER_CASE` имена по PEP 8.
4. Если вам нужен синглтон (один экземпляр), это не статический класс. Синглтон создаёт объект, статический класс — нет.
5. При наследовании статических классов помните, что `@staticmethod` в потомках можно переопределить, а `@classmethod` — да.
6. Для простой группировки утилит без наследования — **используйте модуль** (это будет понятнее для других разработчиков).

## 7. Полный рабочий шаблон статического класса

```python
class StaticClassTemplate:
    """
    Шаблон статического класса.
    Все методы и атрибуты — статические, создание экземпляров запрещено.
    """

    # Статические атрибуты (константы)
    CONSTANT = 42

    def __new__(cls, *args, **kwargs):
        """Запрещаем создание экземпляров."""
        raise TypeError(f"{cls.__name__} is a static class and cannot be instantiated")

    @staticmethod
    def utility_function(param):
        """Пример статического метода."""
        return param * StaticClassTemplate.CONSTANT

    @classmethod
    def class_method_example(cls, value):
        """Доступ к атрибутам класса (включая переопределённые в подклассах)."""
        return value + cls.CONSTANT
```

**Использование:**

```python
# Правильно
print(StaticClassTemplate.utility_function(10))  # 420
print(StaticClassTemplate.class_method_example(5)) # 47

# Неправильно — вызовет исключение
# obj = StaticClassTemplate()
```

## 8. Заключение

Статический класс в Python — это **искусственная конструкция**, эмулирующая поведение одноимённой сущности из статически типизированных языков. Она реализуется путём:
- помещения всех методов под `@staticmethod` или `@classmethod`;
- запрета инстанцирования через `__new__`;
- использования атрибутов класса для хранения общих данных.

Тем не менее, **в Python предпочтительнее использовать модули** для тех же целей. Статический класс выбирают, когда важны наследование, полиморфизм или единая ООП-стилистика проекта. В любом случае, чётко документируйте назначение такого класса, чтобы не вводить в заблуждение других разработчиков.
